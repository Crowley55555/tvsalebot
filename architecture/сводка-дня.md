# Сводка дня — архитектура tvsalebot

> Короткий итог: что мы строим, пять главных решений, что в этот круг не идёт, главный риск, с чего начинаем завтра.
> Это **индекс**, не замена чертежу: подробности — в [00-правила-проекта.md](00-правила-проекта.md), [01-что-строим.md](01-что-строим.md) … [10-план-реализации.md](10-план-реализации.md), журнал — в [decisions.md](decisions.md).

## Что строим (один абзац)

**tvsalebot** — Telegram-бот + Core API (FastAPI) на Python, который за 5–10 минут живого диалога подбирает человеку 2–3 телевизора Samsung под его комнату, бюджет и сценарий просмотра, а потом тонко предлагает магазину-клиенту заказать такого же в свой магазин. Собираем MVP для одного конкретного регионального дилера Samsung TV: без каталога магазина, на 12–14 моделях Samsung, которые бот «знает»; LLM — GigaChat 2 Pro через Freemium 40 млн токенов в год (0 ₽ до первого контракта); контекст — Redis; на проде добавляется PostgreSQL для долговечной истории, лидов и каталога. Срок — 3–4 недели, бюджет — 60–80 часов моей работы; цель — не бот как продукт, а демо-ссылка, которая принесёт заказ на полноценную разработку.

## Главные пять архитектурных решений

1. **Пять портов домена + адаптер на каждого вендора.** `LLMClient`, `ContextStore`, `TVCatalog`, `ErrorReporter`, `AlertSink` живут в `domain/ports/`; реализации — в `infrastructure/<kind>/<vendor>.py` (имя файла = имя вендора). Смена вендора = новый файл + одна строка в `.env`. Правило П2 из [00-правила-проекта.md](00-правила-проекта.md), все пять портов перечислены в [05-стек.md § «Порты и адаптеры»](05-стек.md).
2. **Вертикальные срезы фич в `features/`, не слоистый DDD, не монолит одного `core/`.** Пять фич MVP — `dialog`, `consent`, `deletion`, `recommendation`, `b2b` — каждая в своей папке с одной публичной функцией-дверью через `__init__.py`. Правка одной фичи не трогает другие, параллельная работа на пяти окнах Claude — без конфликтов ([08-структура-кода.md](08-структура-кода.md)).
3. **ПДн граждан РФ физически не покидают РФ-контур.** aiogram + Core API + Redis живут на РФ-сервере; NL-сервер — **только** SOCKS5-прокси для исходящих TLS-туннелей к `api.telegram.org`. Трансграничная передача по ст. 12 ФЗ-152 не задействована, уведомление РКН до старта MVP не требуется ([05-стек.md § «Хостинг»](05-стек.md), выбор защищает от смертельного риска С4 из [09-риски.md](09-риски.md)).
4. **Промпт — главный актив, живёт отдельно от кода.** Все 12–14 моделей, роль Samsung-эксперта, формулировки воронки, политика ФЗ-152, тексты КП — в `prompts/*.md`. Правка промпта не требует релиза; в `api/`, `bot/`, `features/`, `domain/`, `infrastructure/` ни одной строки продающего текста и ни одной цифры из спецификации Samsung TV (правило П1, проверка грепом в [00-правила-проекта.md](00-правила-проекта.md)).
5. **Защита Freemium с первого дня — не «на прод».** Prompt caching стабильного блока в GigaChat (система + модели — цена падает в 5–10 раз) + фильтрация 12–14 моделей по сценарию и бюджету (3–4 релевантных вместо всех) + укорочение истории с 20 до 10 реплик + авто-стоп на 100 000 токенов/день в `infrastructure/llm/budget.py`. Иначе Freemium 40 млн токенов/год исчерпывается за полтора месяца на одной отладке промпта — закрыт смертельный риск С3 из [09-риски.md](09-риски.md).

## Что НЕ делаем

- Интеграция с реальным каталогом клиента, CRM (Битрикс24/amoCRM), WhatsApp, веб-виджет, голосовой канал, админ-панель для правки промпта, аналитика диалогов и воронки, A/B-тесты, автогенерация промпта под нового клиента, мультиязычность, голосовые сообщения в TG (STT), приём платежей в самом боте — всё это бэклог «после первого контракта» ([01-что-строим.md § «Что НЕ войдёт»](01-что-строим.md), [idea/mvp.md § 7](../idea/mvp.md)).
- Микросервисы, event-sourcing, Kubernetes, собственная LLM на Ollama, OpenAI/Claude в проде, MongoDB, Kafka, Celery, GitLab Runner CI/CD, Grafana+Prometheus, webhook Telegram, gRPC между Core и bot, Admin-UI — список осознанных отказов в [05-стек.md § «Что я сознательно НЕ выбрал»](05-стек.md).

## Главный риск

**Трансграничная передача ПДн граждан РФ через NL-сервер без уведомления РКН — штраф по ст. 13.11 КоАП от 150 тыс. ₽, кейс фитнес-клубов — 25 млн ₽ за Google Analytics (С4 из [09-риски.md](09-риски.md)).** Закрыт выбранной архитектурой: NL-сервер работает только как SOCKS5-прокси, aiogram и Core API живут на РФ-сервере, TLS-туннель к Telegram API устанавливается из РФ и зашифрован на уровне транспорта — NL видит только `CONNECT api.telegram.org:443`, не содержимое. Fallback — схема A с ручным уведомлением РКН, активируется через `TELEGRAM_PROXY_MODE=direct` если NL-провайдер заблокирует SOCKS5.

## С чего начинаем завтра

**F5 — Walking Skeleton.** Сквозной тонкий срез Telegram → Core API → GigaChat → Telegram, с минимальным промптом на 3–5 моделей и consent-гейтом ФЗ-152. Приёмочные сценарии А1–А5 — в [10-план-реализации.md § 3](10-план-реализации.md). Промт для нового окна Claude (с Plan Mode) — в [10-план-реализации.md § 5](10-план-реализации.md), скопировать и запустить в свежем окне завтра.

До того как первые строки кода написаны — **короткая первая связь с клиентом** (без готового бота: «идея-гипотеза, интересно ли в принципе») + сбор 2–3 запасных контактов из того же сегмента региональных дилеров Samsung. Это закрывает коммерческий риск С1 из [09-риски.md](09-риски.md), пока разработка идёт.
