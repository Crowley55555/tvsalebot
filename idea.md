# Техническое задание и архитектура: MVP Бота-консультанта по продаже телевизоров Samsung

## 1. Цель проекта
Разработать MVP (демо-версию) Telegram-бота, который выступает не как простой поисковик по базе, а как **опытный консультант-продажник** телевизоров Samsung. 
Цель демо — показать клиенту магию живого диалога, выявление потребностей и экспертные рекомендации, чтобы получить绿灯 (зеленый свет) на полноценную разработку с интеграцией в реальный каталог.

## 2. Архитектура проекта (Критически важно!)
Проект должен быть строго разделен на два независимых модуля. Это задел на будущее, чтобы к этой же логике можно было подключить WhatsApp, веб-виджет или голосового ассистента.

### Модуль А: Core API (Бэкенд / Мозги)
- Отвечает за всю бизнес-логику, хранение контекста диалога и взаимодействие с LLM.
- Принимает текстовое сообщение от пользователя + `user_id` + `session_id`.
- Возвращает текстовый ответ и, при необходимости, структурированные данные (например, JSON с рекомендованными моделями, если они потом будут подтягиваться из БД).
- Реализовать на **FastAPI**.

### Модуль Б: Telegram Bot (Фронтенд / Обертка)
- Отвечает ТОЛЬКО за прием сообщений в Telegram и отправку ответов из API.
- Не содержит никакой бизнес-логики и промптов. Просто проксирует запросы к Core API.
- Реализовать на **aiogram 3.x** (асинхронно).

## 3. Стек технологий
- **Язык:** Python 3.10+
- **API:** FastAPI, Pydantic (для схем данных), Uvicorn.
- **Bot:** aiogram 3.x.
- **LLM Integration:** OpenAI API (или Anthropic/локальная модель через LiteLLM) для генерации ответов.
- **State Management:** Redis (для хранения контекста диалога и истории сообщений между сессиями API).
- **База данных (MVP):** На этапе MVP база данных с каталогом НЕ НУЖНА. LLM должна использовать свои внутренние знания о популярных моделях Samsung (или мы захардкодим 3-5 моделей в промпт для теста).

## 4. Бизнес-логика и Промпт для LLM (Роль "Продажника")
LLM должна работать по строгому системному промпту. Она НЕ должна просто выдавать список товаров. Она должна вести диалог.

**Системный промпт (Роль):**
"Ты — элитный консультант-эксперт по продаже телевизоров Samsung в официальном магазине. Твоя задача — не просто ответить на вопрос, а помочь клиенту выбрать идеальный телевизор, задавая правильные вопросы. Ты общаешься дружелюбно, экспертно, без навязчивости. Ты не выдаешь весь список вопросов сразу, а ведешь диалог шаг за шагом."

**Алгоритм выявления потребностей (Воронка):**
Бот должен последовательно (по одному вопросу за раз) выяснить:
1. **Цель использования:** "Для чего в основном будет телевизор? (Просмотр кино/сериалов, спорт, игры на PS5/Xbox, просто фоном?)"
2. **Условия размещения:** "В какую комнату планируете ставить и какое примерное расстояние от дивана до экрана?" (Чтобы подобрать диагональ).
3. **Бюджет:** "В каком бюджете рассматриваем?"
4. **Ключевые фишки:** (Если игры -> упор на HDMI 2.1, 120Hz, VRR. Если кино -> упор на OLED/Neo QLED, глубокий черный, Dolby Vision).

**Правила общения:**
- Задавать только ОДИН уточняющий вопрос за раз.
- Если клиент спрашивает "посоветуй телевизор", не давать ответ сразу, а начать воронку.
- Отработать возражения (например, "дорого" -> предложить альтернативу из той же линейки, но чуть дешевле, объяснив разницу).
- В финале предложить 2-3 конкретные модели с кратким обоснованием, ПОЧЕМУ они подходят именно под его запросы.

## 5. План реализации (Шаги для AI-кодера)

**Шаг 1: Инициализация проекта**
- Создать структуру папок: `/api`, `/bot`, `/core` (для промптов и работы с LLM), `/config`.
- Настроить `requirements.txt` и `.env`.

**Шаг 2: Разработка Core API**
- Написать эндпоинт `POST /chat`.
- Реализовать модуль работы с LLM (отправка системного промпта + истории сообщений).
- Настроить хранение контекста (в памяти или Redis).

**Шаг 3: Разработка Telegram Бота**
- Настроить хэндлеры aiogram.
- Реализовать отправку запросов к Core API и возврат ответов пользователю.
- Добавить команду `/start` с приветствием и командой `/reset` для сброса диалога.

**Шаг 4: Интеграция и тестирование**
- Запустить API и Бот.
- Протестировать сценарий: пользователь пишет "Хочу телек", бот начинает воронку, выясняет про PS5 и комнату 20 метров, рекомендует Neo QLED с HDMI 2.1.

## 6. Важные примечания для кодера
- Код должен быть чистым, типизированным (используй Pydantic) и следовать принципам SOLID.
- Разделение на API и Бот — строгое. Бот не должен знать, как работает LLM.
- Промпт для LLM вынести в отдельный файл или константу, чтобы его было легко редактировать.
- На этапе MVP не пиши парсеры сайтов или сложные БД. Сфокусируйся на качестве диалога и логики продаж.
