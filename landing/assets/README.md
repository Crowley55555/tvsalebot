# landing/assets — реальные скриншоты для лендоса

Эта папка — единственное место в репозитории, где разрешены медиа-файлы (`.png`, `.jpg`, `.webp`, `.svg`). См. [.gitignore](../../.gitignore) правило `!landing/assets/**` и [architecture/00-правила-проекта.md П7-а](../../architecture/00-правила-проекта.md).

## Что положить

Скриншоты из рабочего Telegram-бота после пяти эталонных сценариев из [idea/proof-of-value.md § 2](../../idea/proof-of-value.md):

| Файл | Что должно быть на скриншоте |
|---|---|
| `dialog-1.png` | Сценарий 1 — «телек в гостиную»: бот задаёт вопросы, не вываливает топ-5. |
| `dialog-2.png` | Сценарий 2 — «у меня PS5»: уточнение про 4K@120 и VRR, отсечение HDMI 2.0. |
| `dialog-3.png` | Сценарий 3 — OLED vs QLED: ответ через сценарий, а не через технологию. |
| `dialog-4.png` | Сценарий 4 — Dolby Vision: честный ответ, готовность отправить к LG. |
| `dialog-5.png` | Сценарий 5 — кухня до 50 тыс.: Crystal UHD без впаривания в Q60. |

**Пропорции:** вертикальные, под мобильный Telegram, рекомендуется 1080×1920 или 1170×2532. Макет лендоса растянет их в сетку `aspect-ratio: 9 / 16`.

**ПДн на скриншотах:** если видно `telegram_id`, настоящее имя или телефон — замазать перед сохранением.

## Что заменить в `index.html` после появления PNG

Сейчас в `landing/index.html` на месте скриншотов — текстовые реплики-заглушки внутри `<article class="screen">`. Как только PNG появятся, заменить каждый `<article>` на:

```html
<article class="screen" role="listitem">
  <img src="assets/dialog-1.png" alt="Диалог с ботом: сценарий 1 — подбор ТВ в гостиную" loading="lazy">
</article>
```

и удалить правила `.screen-head`, `.screen-body`, `.msg`, `.screen-placeholder` из `<style>`, если они больше не нужны.
