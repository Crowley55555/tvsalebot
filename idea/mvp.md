# MVP

## Как надиктовал

> Отдельной надиктовки по MVP не было — файл собран из [idea.md](../idea.md), [proof-of-value.md](proof-of-value.md), [deep-research.md](deep-research.md), [principles.md](principles.md). Допущения по срокам и ставке явно помечены — поправь, если расходятся с реальностью.

## Ядро

**MVP = демо-ядро «AI-продажник Samsung TV» на 12–14 захардкоженных моделях, которое можно отдать клиенту как ссылку на TG-бот и получить заказ на полноценную разработку.**

Критически важно: это **НЕ производственная версия**. Нет каталога, нет CRM, нет WhatsApp, нет аналитики. Есть **ядро диалога + Telegram-обёртка + 5 отрабатываемых сценариев**.

## 1. Scope MVP

### 1.1. Что входит ✅

| Компонент | Что это |
|---|---|
| **Core API (FastAPI)** | `POST /chat` принимает `{user_id, session_id, message}` → возвращает `{reply}`. Хранит контекст в Redis. |
| **Telegram-бот (aiogram 3.x)** | Хэндлеры `/start`, `/reset`, `/для_магазина`, свободные сообщения. Проксирует в Core API. |
| **Системный промпт** | Роль Samsung-эксперта. Воронка вопросов. 12–14 моделей ТВ (OLED S95/S90, Neo QLED QN900/QN90/QN85, QLED Q80/Q60, Crystal UHD, Lifestyle Frame) с ценами-вилками. |
| **LLM-интеграция** | GigaChat 2 Pro через Freemium (40 млн токенов/год бесплатно). |
| **Хранение контекста** | Redis. История диалога + мета (бюджет, комната, сценарий, консоль). |
| **Согласие ФЗ-152** | Кнопка на старте, политика ссылкой, команда `/stop` для отзыва. |
| **Лендос-одностраничник** | Отдельный HTML или Tilda-страница с описанием продукта (без цен). |
| **Короткое КП** | Notion/PDF, 1–2 экрана. Отправляется только по запросу. |
| **README + инструкция запуска** | Для себя и для будущего передающего в прод. |

### 1.2. Что НЕ входит ❌ (в бэклог «после первого контракта»)

- Интеграция с реальным каталогом клиента (БД / парсер его сайта).
- WhatsApp Business API.
- Веб-виджет для сайта магазина.
- Голосовой ассистент.
- CRM-интеграция (Битрикс24, amoCRM).
- Админ-панель для правки промпта.
- Аналитика диалогов, конверсий, воронки.
- Голосовые сообщения в TG (STT).
- Мультиязычность (бот только на русском).
- A/B-тесты вариантов промпта.
- Автогенерация промпта под нового клиента по его сайту.

### 1.3. Что НЕ пишем сами, берём готовое

- VPS (Timeweb/Beget), не собственная инфраструктура.
- Redis Managed (Yandex Cloud / Timeweb), не свой кластер.
- Любая аналитика в MVP — нет; UptimeRobot для мониторинга.
- Лендос — Tilda / конструктор, не вёрстка руками (если нет готового UI-скелета).

## 2. Технический стек

| Слой | Технология | Причина |
|---|---|---|
| Язык | Python 3.11+ | Актуальный, нативная асинхронность. |
| API | FastAPI + Uvicorn | Де-факто стандарт для LLM-бэкендов. |
| Схемы | Pydantic v2 | Валидация запросов/ответов. |
| Bot | aiogram 3.x | Основной стек, зрелая FSM. |
| LLM | GigaChat 2 Pro (Freemium) | ФЗ-152 из коробки, 40 млн токенов на год бесплатно. YandexGPT как fallback. |
| State | Redis | Контекст диалога. Пережить рестарт сервиса. |
| Хостинг | VPS Timeweb/Beget (~500–800 ₽/мес) | Простое и дешёвое. |
| Логи | stdout → journald | Для MVP хватает. |
| Мониторинг | UptimeRobot | Бесплатный пинг каждые 5 мин. |
| Лендос | Tilda / простой HTML | Быстро, без вёрстки. |

**Абстракция LLM-клиента обязательна** — на случай замены Gigachat → YandexGPT → OpenRouter без переписывания бизнес-логики.

## 4. План по этапам (с оценкой часов)

> **Допущение:** работаю ~15–20 часов в неделю при текущей загрузке. При темпе 2 часа в день + 5 часов в выходной — 20 часов. Общая оценка — **~60–80 часов**, срок **3–4 недели** от старта. Если допущение неверно, поправь — пересчитаю.

### Этап 1. Инициализация + «hello world» LLM (6–10 часов)

- Структура папок, `.gitignore`, `requirements.txt`.
- `.env` + `.env.example` (с именами переменных, значения — локально).
- Регистрация в developers.sber.ru, получение API-ключа GigaChat.
- **Простой скрипт `scripts/smoke_llm.py`**: отправить «привет» в GigaChat → получить ответ. **Это проверка, что ключи, биллинг, Freemium работают.**
- Регистрация бота в @BotFather, токен.
- Простой aiogram-бот, который на `/start` отвечает «работает».

**Deliverable этапа:** два простых скрипта работают независимо. Основная цель — снять интеграционные риски до того, как написана бизнес-логика.

### Этап 2. Core API (12–16 часов)

- FastAPI проект, Uvicorn.
- Pydantic-схемы `ChatRequest / ChatResponse`.
- Эндпоинт `POST /chat`.
- Абстракция `core/llm.py` с интерфейсом + реализация `GigaChatClient`.
- Redis-клиент (`core/context.py`): `get_history(user_id)` / `append_message(user_id, msg)`.
- Склейка: `/chat` → достать историю → отправить в LLM с системным промптом → сохранить ответ → вернуть клиенту.
- Эндпоинт `POST /reset` для сброса контекста.
- Простая проверка через curl / Postman.

**Deliverable:** API локально работает, умеет вести диалог через curl.

### Этап 3. Telegram-бот (8–10 часов)

- aiogram 3.x, роутеры, FSM на уровне команд.
- Хэндлер `/start` — приветствие + кнопка согласия ФЗ-152 (блок до согласия).
- Хэндлер `/reset` — сброс через Core API.
- Хэндлер `/для_магазина` — отправка КП-текста.
- Хэндлер `/stop` — отзыв согласия, удаление данных.
- Хэндлер text-сообщения — проксирование в Core API.
- Клавиатуры с кнопками для фиксированных ответов (кино/спорт/игры/фон).
- Обработка ошибок LLM: «секунду, перезапрашиваю» вместо стек-трейса.

**Deliverable:** бот локально принимает сообщения, крутит их через API, отвечает в TG.

### Этап 4. Промпт и 12–14 моделей (12–16 часов) — **главная работа**

- Файл `prompts/system.md` — роль Samsung-эксперта.
- Файл `prompts/models.md` — 12–14 моделей с: класс, диагонали, Hz, нит, HDMI, подсветка, цена-вилка, «кому подойдёт». Данные — из [deep-research.md § 3](deep-research.md).
- Правила воронки (один вопрос за раз, сценарий первее характеристик).
- Правила честности (нет Dolby Vision, Crystal UHD не QLED, 8K-контента почти нет).
- Правила тон/язык (русский человеческий, короткие сообщения).
- Финальный блок «как безопасно принять ТВ».
- **Итерации.** Каждый цикл: прогон 5 эталонных сценариев → фикс промпта → повтор.
- Параллельный тест с голым ChatGPT: наш бот должен отличаться.

**Deliverable:** 5 эталонных сценариев из [proof-of-value.md § 2](proof-of-value.md) проходят безупречно.

### Этап 5. ФЗ-152 — согласия и политика (4–6 часов)

- Текст политики обработки ПДн (можно по шаблону из [BotHelp](https://bothelp.io/ru/blog/kak-rabotat-personalnymi-dannymi-chat-botah)).
- Загрузка политики на лендос (отдельная страница `/privacy`).
- Кнопка согласия в `/start`, блокировка диалога до согласия.
- Второе согласие (на рассылку/маркетинг) — опционально, пока без него.
- Команда `/stop` — отзыв + удаление данных пользователя из Redis.
- В README — пункт «заказчик должен быть зарегистрирован как оператор ПДн».

**Deliverable:** согласие работает, политика доступна, `/stop` удаляет данные.

### Этап 6. Лендос + КП (6–8 часов)

- Tilda / простой HTML — одна страница.
- Структура из [proof-of-value.md § 5.1](proof-of-value.md): заголовок, скриншоты диалога (сначала рисуем от руки), что получает магазин, как работает за 60 сек, сроки, контакт.
- Снимаем 3–5 скриншотов из рабочего бота.
- КП как Notion-страница / PDF, 1–2 экрана. Цена **только последним пунктом**, идеально — не в документе, а в личной переписке.

**Deliverable:** есть ссылка на лендос и ссылка на КП, обе работают.

### Этап 7. Деплой + мониторинг (4–6 часов)

- VPS Timeweb/Beget, минимальная настройка (nginx, systemd для api и bot).
- Redis Managed или `docker-compose up` на той же машине.
- `.env` с продовыми ключами GigaChat.
- Фоновый прогон smoke-теста после каждого рестарта.
- UptimeRobot: пинг `/health` каждые 5 минут.
- Домен для лендоса (если нужен).

**Deliverable:** бот и API работают 24/7 на боевом VPS.

### Этап 8. Внутренний QA + внешние тестеры (6–8 часов)

- Самостоятельный прогон 5 сценариев + провокации ([proof-of-value.md § 6](proof-of-value.md)).
- 2–3 знакомых тестируют вслепую. Собираем фидбек: где «ботит», где скучно, где непонятно.
- Правка промпта по фидбеку.
- Финальный прогон перед отправкой клиенту.

**Deliverable:** чек-лист из [proof-of-value.md § 6](proof-of-value.md) закрыт, бот готов к показу.

### Итого по этапам

| Этап | Часы (вилка) | Срок при 20 ч/нед |
|---|---|---|
| 1. Инициализация + hello world | 6–10 | 2–3 дня |
| 2. Core API | 12–16 | 3–4 дня |
| 3. Telegram-бот | 8–10 | 2–3 дня |
| 4. Промпт + модели (главное) | 12–16 | 3–4 дня |
| 5. ФЗ-152 | 4–6 | 1–2 дня |
| 6. Лендос + КП | 6–8 | 2 дня |
| 7. Деплой + мониторинг | 4–6 | 1–2 дня |
| 8. QA | 6–8 | 2–3 дня |
| **Итого** | **58–80 часов** | **3–4 недели** |

## 5. Критерии готовности к демо (Definition of Done)

Прежде чем давать клиенту ссылку, выполнены **все** пункты:

- [ ] 5 эталонных сценариев отрабатывают без запинок.
- [ ] Параллельный тест с голым ChatGPT — наш бот звучит иначе (короче, конкретнее, с цифрами).
- [ ] 2–3 внешних тестера прошли и дали фидбек, фидбек учтён.
- [ ] Чек-лист провокаций ([proof-of-value.md § 6.2](proof-of-value.md)) закрыт.
- [ ] Согласие ФЗ-152 работает, `/stop` удаляет данные.
- [ ] UptimeRobot мониторит API — последние 24 часа без падений.
- [ ] Лендос онлайн, скриншоты вставлены, цен нет.
- [ ] КП готов (в черновике Notion/PDF), не отправляется до запроса.
- [ ] README проекта актуален.
- [ ] `.env` не в репо, приватные данные не в коммитах.

## 6. Расчёт стоимости для себя (приватный)

> **Допущения, подлежащие уточнению:**
> - Ставка **1000 ₽/ч** — из глобальных правил проекта.
> - Общее время **58–80 часов** (пессимистично-реалистично).
> - Маржа **50–100%** сверх себестоимости — покрытие рисков (правки клиента, простой API, собственное время на коммуникацию).
> - Накладные расходы: VPS ~800 ₽/мес × 1–3 мес сопровождения, домен ~200 ₽/год, лендос Tilda ~700 ₽/мес, GigaChat Freemium = 0 ₽ на период MVP.

### Себестоимость часов

| Строка | Расчёт | Сумма |
|---|---|---|
| Минимум часов × ставка | 58 × 1000 ₽ | **58 000 ₽** |
| Максимум часов × ставка | 80 × 1000 ₽ | **80 000 ₽** |

### Накладные (3 месяца)

| Строка | Сумма |
|---|---|
| VPS (3 мес) | 2 400 ₽ |
| Домен (год) | 200 ₽ |
| Tilda Lite (3 мес) | 2 100 ₽ |
| GigaChat Freemium | 0 ₽ |
| **Итого накладные** | **~4 700 ₽** |

### Итоговая себестоимость

- Минимум: 58 000 + 4 700 = **~62 700 ₽**
- Максимум: 80 000 + 4 700 = **~84 700 ₽**

### Цена для клиента (вилка)

Накидываем маржу 50–100% + округляем до «красивых» чисел:

| Сценарий | База + маржа | Округлённо (клиенту) |
|---|---|---|
| **«Нежадный»** (маржа 50% на минимуме) | 62 700 × 1,5 ≈ 94 000 | **~90 000 ₽** |
| **«Стандарт»** (маржа 75% на среднем) | 73 700 × 1,75 ≈ 129 000 | **~130 000 ₽** |
| **«Премиум»** (маржа 100% на максимуме) | 84 700 × 2 ≈ 169 000 | **~170 000 ₽** |

**Рабочая стратегия:**
- Если клиент сам спросил цену первым — называем **130 000 ₽** как основной.
- Если торгуется — не сбрасываем цену, а урезаем scope (например, без лендоса / без ФЗ-152-обвязки, под ответственность заказчика).
- Нижняя граница, ниже которой не идём — **90 000 ₽**. Иначе проект убыточен.
- Форма оплаты: **50% предоплата + 50% по приёмке**. Без исключений.

**Эта таблица — приватный расчёт, в КП и на лендосе не публикуется.** В КП клиенту указывается только итоговая цена и формат оплаты.

## 7. Что идёт в бэклог «после первого контракта»

Чтобы в MVP было тяжело «срываться на интересное» (см. [risks.md § 4.2](risks.md)), фиксируем явный бэклог. **Это НЕ MVP, обсуждается только после подписания основного контракта.**

### Приоритет 1 (сразу после MVP, если клиент хочет полную разработку)
- Интеграция с реальным каталогом клиента (БД моделей + цены + остатки).
- Админ-панель для правки промпта / каталога.
- Передача горячих лидов в CRM клиента (Битрикс24 / amoCRM / Google Sheets).

### Приоритет 2 (расширение каналов)
- Веб-виджет для сайта магазина (JS + API).
- WhatsApp Business API.
- Если актуально — VK Bot API.

### Приоритет 3 (качество)
- Аналитика диалогов и воронки (сколько дошли до рекомендации, сколько запросили контакт).
- A/B-тесты вариантов промпта.
- Голосовые сообщения в TG (STT через SaluteSpeech / Yandex SpeechKit).

### Приоритет 4 (переупаковка в SaaS, см. [vision.md](vision.md))
- Шаблонизация промпта под нового клиента по его сайту (автогенерация).
- Самостоятельное подключение магазина через конструктор.
- Биллинг / тарифы / админка арендатора.
- Переход на вариант Б/В из [vision.md](vision.md).

## 8. План первой недели (что делать прямо сейчас)

1. **Связаться с клиентом коротко** (без готового бота) — рассказать идею в 3–5 предложениях, спросить «интересно ли в принципе». Это закрывает главный риск «клиент остынет» ([risks.md § 1.1](risks.md)).
2. **Параллельно собрать 2–3 запасных контакта** в сегменте региональных Samsung-дилеров — страховка.
3. **Начать Этап 1** — зарегистрироваться на developers.sber.ru, получить ключ GigaChat, прогнать smoke-тест LLM. Этот шаг снимает интеграционный риск до того, как написана остальная логика.
4. **Создать репозиторий** со структурой из § 3. Пустые файлы, но каркас готов.
5. **Проверить допущения из этого файла** (часы в неделю, срок, ставка) — если расходятся с реальностью, перепланировать таблицу § 4 и § 6.
